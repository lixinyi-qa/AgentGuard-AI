# 测试案例目录

机器可执行详情在 `data/evaluation_cases.json`。每条记录都包含 case_id、标题、类别、角色、输入、目标、可用工具、故障、期望工具/参数、禁止工具、审批、策略、关键词、来源、拒绝、风险、严重程度和描述。

| 范围 | Case ID | 重点 |
|---|---|---|
| 正常任务 | AG-001～008 | 账户、交易、政策、联系方式、退款、工单 |
| 角色/对象权限 | AG-009～015 | 匿名、跨账户、跨交易、撤销授权、审计、客服批量 |
| AI 安全 | AG-016～022 | 直接/间接注入、系统提示词、Key、PII、过度代理、恶意输出 |
| 故障恢复 | AG-023～032 | timeout、500、429、空/缺/错类型/畸形、陈旧、DB、部分成功 |
| 幂等与边界 | AG-033～036 | 重复回调、相同请求、邮箱边界、权限服务不可用 |
| 工具/拒绝/审批 | AG-037～040 | 白名单、无依据、not found、已审批高额退款 |

补充自动化：

- 单元测试直接覆盖 Policy 分支、Schema、PII、Injection、百分位、故障消费和重放序列化。
- API 测试覆盖统一错误、资源 404、未知工具 422 和幂等冲突 409。
- UI 测试覆盖操作路径、下载、焦点和移动布局。
- Newman 以环境变量顺序传递 request、trace、fault、run、baseline 和 candidate ID。

Fault 案例是 `injected defect / training exercise / regression fixture`，不是实际生产缺陷。
